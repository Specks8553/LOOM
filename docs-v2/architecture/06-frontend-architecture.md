## Routing Model

No router library. Three mutually exclusive app phases rendered conditionally in `App.tsx`:

```tsx
// App.tsx — simplified
const appPhase = useAppStore(s => s.appPhase);

if (appPhase === 'onboarding') return <OnboardingWizard />;
if (appPhase === 'locked')     return <LockScreen />;
return <Workspace />;
```

`appStore.appPhase`: `"onboarding" | "locked" | "workspace"`

Phase transitions are triggered by Tauri command results, never by URL or navigation events.

### Modes — workspace sub-state

Within `<Workspace />`, the active mode is a sub-state in `modeStore`. It changes what the Theater and Control pane render, but does not change the app phase.

```tsx
// Workspace.tsx — simplified
const activeMode = useModeStore(s => s.activeMode);
// Theater and RightPane receive activeMode as a prop or read it directly
```

`modeStore.activeMode`: `"story" | "handover" | "consulting"`

Only `story` mode is fully implemented. Additional modes are WIP — see Doc 23 (Modes).

## Store Ownership Map

Seven stores with explicit, non-overlapping domains. Defined in D-03 and amended in D-03-B.

### `appStore`
**Owns:** App phase, viewport dimensions, toast queue, which modals are open.
**Does not own:** Any domain data, user content, or settings.

```typescript
interface AppStore {
  appPhase: 'onboarding' | 'locked' | 'workspace';
  viewport: { width: number; height: number };
  toasts: Toast[];
  activeModal: 'settings' | 'worldPicker' | null;
  rightPaneCollapsed: boolean;
  // actions
  setPhase: (phase: AppPhase) => void;
  pushToast: (toast: Toast) => void;
  dismissToast: (id: string) => void;
  openModal: (modal: 'settings' | 'worldPicker') => void;
  closeModal: () => void;
  setRightPaneCollapsed: (value: boolean) => void;
}
```

**Naming:** the state field is `activeModal` (a value); the action is `openModal` (a verb). They previously collided under the same name.

### `authStore`
**Owns:** Whether the vault is locked, whether an API key is configured (boolean only), the auto-lock timer.
**Does not own:** The master key, API key bytes, or PBKDF2 salt (those never leave Rust).

The full shape is defined in **Doc 13 (Auth and Onboarding)** — that document is authoritative. Summary:

```typescript
interface AuthStore {
  isLocked: boolean;        // matches appPhase === 'locked'
  hasApiKey: boolean;       // boolean only — key bytes never in frontend
  autoLockSecs: number;
  autoLockTimerHandle: ReturnType<typeof setTimeout> | null;
  // actions
  unlock(): Promise<void>;
  lock(): void;
  startAutoLockTimer(): void;
  resetAutoLockTimer(): void;
  clearAutoLockTimer(): void;
  setHasApiKey(val: boolean): void;
}
```

### `vaultStore`
**Owns:** The vault tree (all worlds, items, folders), selection state, filter text, trash visibility.
**Does not own:** Active story content, settings, or message data.

```typescript
interface VaultStore {
  worlds: WorldMeta[];
  activeWorldId: string | null;
  activeWorldDir: string | null;       // absolute path; populated on world open (Doc 19 uses for convertFileSrc)
  items: VaultItemMeta[];              // live items only (deleted_at IS NULL)
  trashItems: VaultItemMeta[];         // soft-deleted items; loaded lazily when isTrashView = true
  selectedIds: Set<string>;            // O(1) membership test; idiomatic Zustand
  expandedFolderIds: string[];         // mirrored to localStorage
  filterQuery: string;
  isTrashView: boolean;
  // actions
  setWorlds: (worlds: WorldMeta[]) => void;
  loadVault: () => Promise<void>;
  loadTrash: () => Promise<void>;
  setItems: (items: VaultItemMeta[]) => void;
  setSelected: (ids: Set<string>) => void;
  toggleSelection: (id: string) => void;
  setFilter: (query: string) => void;
  toggleExpanded: (folderId: string) => void;
  setTrashView: (val: boolean) => void;
  clear: () => void;                   // called on world switch and lock
}
```

Field-name and type contract is locked here (consultant pass result of pre-impl audit CD-7); Doc 14's narrative may use friendlier names in prose but the canonical TypeScript shape lives in this file.

### `workspaceStore`
**Owns:** Active story ID, active doc ID, message list, streaming state, accordion segments + checkpoints, ghostwriter state.
**Does not own:** Settings, vault tree, mode.

Accordion state is held here (not in a separate store) because segments and checkpoints are story-scoped, load with the story, and form a small list that always travels with `messages`. See Doc 16.

```typescript
interface WorkspaceStore {
  activeStoryId: string | null;
  activeDocId: string | null;
  messages: ChatMessage[];
  isGenerating: boolean;             // single global flag — story / session / summarise
  streamingMsgId: string | null;
  contextDocIds: string[];

  // Accordion (Doc 16) — story-scoped, reload with story.
  segments: AccordionSegment[];      // closed segments only (open tail has no row)
  checkpoints: Checkpoint[];          // including the start sentinel
  summarisingSegmentId: string | null; // banner-local loading indicator anchor

  // Source documents (Doc 18) — DocEditor surface and per-story attachments.
  activeDocId: string | null;        // when non-null, DocEditor takes the workspace surface
  contextDocIds: string[];           // mirrors story_state.context_doc_ids; insertion order

  // Ghostwriter (Doc 17) — at most one bubble in mode at a time.
  ghostwriter: {
    activeMessageId: string;
    phase: 'selecting' | 'composing' | 'generating' | 'reviewing';
    selection: GhostwriterSelection | null;
    instruction: string;
    diff: DiffSpan[] | null;
    pendingNewContent: string | null;
  } | null;

  // Feedback (Doc 28) — at most one bubble in feedback-edit at a time.
  // The in-progress textarea value lives as local component state inside
  // <AiBubble>; only the *fact* that this bubble is in edit mode is global,
  // so the Escape chain (Doc 11 priority 5) and the implicit-cancel-on-switch
  // rule can read a single flag.
  feedbackEditingMessageId: string | null;

  // actions
  setActiveStory: (id: string | null) => void;
  appendMessage: (msg: ChatMessage) => void;
  setIsGenerating: (value: boolean) => void;

  // Source-document actions (Doc 18) — thin wrappers over commands in commands/vault.rs.
  openDoc: (docId: string) => void;                  // sets activeDocId
  closeDoc: () => Promise<void>;                     // awaits pending debounced save; clears activeDocId
  updateDocContent: (docId: string, content: string) => void;  // schedules ~1 s debounced save
  flushDocSave: () => Promise<void>;                 // forces immediate save (lock / world switch / close)
  attachDoc: (docId: string) => Promise<string[]>;   // returns the new ordered context_doc_ids
  detachDoc: (docId: string) => Promise<string[]>;   // same — frontend updates contextDocIds without a follow-up round-trip
  loadAttachedDocs: () => Promise<void>;             // reads list_attached_docs for active story (defensive reload)

  // Accordion actions — thin wrappers over commands in commands/accordion.rs (Doc 07).
  loadAccordion: (storyId: string) => Promise<void>;
  createCheckpoint: (afterMessageId: string, name: string) => Promise<void>;
  renameCheckpoint: (checkpointId: string, name: string) => Promise<void>;
  deleteCheckpoint: (checkpointId: string) => Promise<void>;       // merges adjacent segments
  summariseSegment: (segmentId: string) => Promise<void>;
  cancelSummarise: (segmentId: string) => Promise<void>;
  editSummary: (segmentId: string, summary: string) => Promise<void>;
  setSegmentCollapsed: (segmentId: string, collapsed: boolean) => Promise<void>;
  setSegmentUseSummary: (segmentId: string, use: boolean) => Promise<void>;

  // Ghostwriter actions (Doc 17) — wrappers over commands/ghostwriter.rs.
  enterGhostwriter: (messageId: string) => Promise<void>;       // shows discard modal if needed
  exitGhostwriter: () => void;
  setGhostwriterSelection: (sel: GhostwriterSelection | null) => void;
  setGhostwriterInstruction: (text: string) => void;
  generateGhostwriter: () => Promise<void>;                     // calls send_ghostwriter_request
  cancelGhostwriterGeneration: () => Promise<void>;
  acceptGhostwriter: () => Promise<void>;                       // calls save_ghostwriter_edit
  rejectGhostwriter: () => void;                                // returns to composing, preserves instruction
  revertGhostwriter: (messageId: string) => Promise<void>;      // calls revert_ghostwriter_edit

  // Feedback actions (Doc 28) — wrappers over update_feedback in commands/conversation.rs.
  beginFeedbackEdit: (messageId: string) => void;               // implicit-cancel any other open edit
  cancelFeedbackEdit: () => void;                               // clears feedbackEditingMessageId
  commitFeedbackEdit: (messageId: string, value: string) => Promise<void>;
                                                                 // calls update_feedback (cached-message
                                                                 // confirmation modal upstream if applicable);
                                                                 // empty/whitespace value clears the field
  // ...
}
```

### `settingsStore`
**Owns:** The merged settings cascade returned by the backend (world overrides on top of app defaults), plus the raw App and raw World maps used by the Settings surface (Doc 20).
**Does not own:** Per-story operational state (`context_doc_ids`, `active_mode`) — that lives in `workspaceStore` and is loaded from `story_state`. There are no per-story user settings in v2.0.

```typescript
interface SettingsStore {
  resolved: ResolvedSettings | null;          // backend-merged cascade (world → app → fallback)
  appRaw: Record<string, string> | null;      // raw app_settings for the App chapter view
  worldRaw: Record<string, string> | null;    // raw world overrides for the World chapter view
  exportFolder: string | null;                // localStorage-backed UI preference

  // resolved-cascade lifecycle
  loadResolvedSettings: () => Promise<void>;          // call on unlock, world switch, and after settings_changed
  loadAppRaw: () => Promise<void>;                    // App chapter open
  loadWorldRaw: () => Promise<void>;                  // World chapter open

  // mutations
  saveAppSetting: (key: string, value: string) => Promise<void>;
  saveWorldSetting: (key: string, value: string) => Promise<void>;
  clearWorldOverride: (key: string) => Promise<void>;
  clearAllWorldOverridesInTab: (tab: SettingsTab) => Promise<number>;

  // developer prompts + templates
  restorePromptDefault: (key: 'prompt_ghostwriter' | 'prompt_accordion_summarise' | 'prompt_accordion_fake_user' | 'prompt_handover_seed' | 'prompt_consulting_seed') => Promise<void>;
  restoreTemplateDefault: (templateId: string) => Promise<void>;

  // validation (mirrored from services/settings.rs via the IPC schema contract)
  validate: (key: string, value: string) => { ok: true } | { ok: false; reason: string };

  // event handler — registered at App root
  handleSettingsChanged: (payload: { scope: 'app' | 'world'; key: string }) => void;
}
```

The store calls `applyTheme()` whenever a resolved value for `accent_color`, `ghostwriter_color`, or `accordion_color` changes — see Doc 20 §`applyTheme()` Contract.

### `modeStore`
**Owns:** Active mode for the open story; the list of `conversation_sessions` rows for that story; the currently-active session ID (if any); session lifecycle actions (start / enter / exit / rename / delete / collapse).
**Does not own:** Story content, vault tree, settings, message lists. Per-session messages live in `workspaceStore.messages` alongside story messages and are grouped by `session_id` at render time.

```typescript
interface ModeStore {
  activeMode: 'story' | 'handover' | 'consulting';
  // The session currently being driven (input writes to it). Null in story mode.
  activeSessionId: string | null;
  // All sessions for the currently-open story (handover and consulting).
  // Used to render banners and the active-session label on the mode switcher.
  sessions: ConversationSession[];

  // Lifecycle actions — implemented on top of commands in commands/modes.rs (Doc 07).
  loadSessions: (storyId: string) => Promise<void>;
  setMode: (mode: AppMode) => Promise<void>;
    // Story tab → exits any active session, sets activeMode='story'.
    // Handover/Consulting tab → calls startNewSession with that kind.
  startNewSession: (kind: 'handover' | 'consulting') => Promise<string>;
  enterSession: (sessionId: string) => Promise<void>;       // banner-driven re-entry
  exitSession: () => Promise<void>;                          // returns to story mode
  renameSession: (sessionId: string, name: string) => Promise<void>;
  deleteSession: (sessionId: string) => Promise<void>;
  setSessionCollapsed: (sessionId: string, collapsed: boolean) => Promise<void>;
  clear: () => void;                                         // story switch / world switch / lock
}
```

The store reads `sessions` to render banners and to power the mode switcher's session-name sub-label. See Doc 23 §Frontend State for the full behavioural contract and event listener registration.

### `cacheStore`
**Owns:** Story cache status per story, session cache status per consulting session, the TTL countdown ticker, and the cache event handlers. Cache lifecycle is server-managed (Gemini-side TTL, fire-and-forget refresh, stale-by-side-effect) and warrants its own store rather than crowding `workspaceStore`. See Doc 22.
**Does not own:** Any message, settings, or vault data.

```typescript
interface CacheStore {
  byStory: Record<string, CacheStatus>;             // CacheStatus shape: see Doc 03
  bySession: Record<string, SessionCacheStatus>;    // Per-consulting-session cache status
  // actions
  loadStoryCache: (storyId: string) => Promise<void>;
  loadSessionCache: (sessionId: string) => Promise<void>;
  handleStoryCacheEvent: (payload: { story_id: string; status: CacheStatus }) => void;
  handleSessionCacheEvent: (payload: { session_id: string; status: SessionCacheStatus }) => void;
  clearStory: (storyId: string) => void;
  clearSession: (sessionId: string) => void;
  clearAll: () => void;                              // world switch / lock
}
```

A single shared `setInterval` ticker re-renders TTL countdowns across all rendered cache rows at 1 Hz. Detail in Doc 22 §Frontend State.

## Store Rules

**1. No cross-store imports.**
Stores never import each other. A store file imports only Zustand, external libraries, and types. **Linted via `import/no-restricted-paths` per Doc 24 §No Cross-Store Imports (SB-2)** — CI fails on violation.

**2. Cross-store composition happens in hooks or components.**
If a component needs data from two stores, it calls both selectors directly:
```tsx
const activeStoryId = useWorkspaceStore(s => s.activeStoryId);
const accentColor   = useSettingsStore(s => s.worldSettings?.accent_color);
```
If the same combination is needed in multiple places, extract it into a custom hook:
```tsx
// hooks/useStoryContext.ts
export function useStoryContext() {
  const activeStoryId = useWorkspaceStore(s => s.activeStoryId);
  const contextDocIds = useWorkspaceStore(s => s.contextDocIds);
  const model         = useSettingsStore(s => s.worldSettings?.text_model_name);
  return { activeStoryId, contextDocIds, model };
}
```

**3. Use selectors, never the full store.**
```tsx
// ✅ correct — only re-renders when activeStoryId changes
const activeStoryId = useWorkspaceStore(s => s.activeStoryId);

// ❌ wrong — re-renders on any store change
const store = useWorkspaceStore();
```

**4. Stores hold data, not derived state.**
Computed values (e.g. "number of attached context docs") are computed in the component or hook, not stored. Exceptions only where the computation is expensive and must be memoised.

## Tauri IPC Conventions

All `invoke()` calls are wrapped in typed async functions in `src/lib/tauriApi/`. No raw `invoke("command_name", {...})` appears in component or store code.

Files are split by domain, mirroring the backend `commands/` modules:

| File | Wraps |
|---|---|
| `tauriApi/auth.ts` | `unlock_vault`, `lock_vault`, `change_password`, `set_api_key` |
| `tauriApi/vault.ts` | World and item CRUD, trash, restore |
| `tauriApi/conversation.ts` | `send_message`, `edit_message`, `delete_message`, `load_messages` |
| `tauriApi/settings.ts` | Settings read/write, story settings |
| `tauriApi/cache.ts` | Cache create, refresh, delete, get state |

Each wrapper is a typed async function:
```typescript
// tauriApi/conversation.ts
export async function sendMessage(
  storyId: string,
  userContent: UserContent,
  mode: AppMode,
): Promise<void> {
  await invoke('send_message', { storyId, userContent, mode });
}
```

**Every wrapper has error handling.** Errors from `invoke()` are caught and surfaced via toast, inline message, or modal per Doc 12 — never silently swallowed.

## Event Flow

### Tauri events → frontend

**Global events** update store state and are relevant to multiple parts of the app. They are registered in dedicated hooks in `src/hooks/` and called exactly once from `App.tsx`:

```tsx
// App.tsx
useWorkspaceEvents(); // registers: message_chunk, message_complete, etc.
useCacheEvents();     // registers: cache_state_changed
```

Each hook is a `useEffect` with listener registration and cleanup:
```typescript
// hooks/useCacheEvents.ts
export function useCacheEvents() {
  useEffect(() => {
    const unlisten = listen<CacheStatus>('cache_state_changed', (event) => {
      useCacheStore.getState().handleCacheEvent(event.payload);
    });
    return () => { unlisten.then(fn => fn()); };
  }, []);
}
```

**Local events** are relevant to only one component and are registered in that component's `useEffect` with cleanup.

### User action → backend

```
User interaction
  → component calls tauriApi wrapper
  → invoke() crosses IPC boundary
  → Rust command handler
  → service / db layer
  → Result returned to frontend
  → store updated
  → component re-renders
```

For streaming responses, the backend emits `message_chunk` events during generation. The global `useWorkspaceEvents` hook receives them and appends to the message list in `workspaceStore`.

## Component Layer Rules

**`layout/`** — structural shell only. Pane components and dividers. No domain logic, no store reads beyond what's needed to show/hide panes. Props-driven where possible.

**`navigator/`, `theater/`, `control/`** — domain content. These read from stores and call `tauriApi` wrappers. They own the UX for their pane.

**`modals/`** — overlay components. Open/close state lives in `appStore`. Content reads from domain stores.

**`modes/`** — mode switcher and mode-specific UI shells. Reads from `modeStore`. WIP.

**`shared/`** — reusable primitives. No store reads. Fully props-driven. If a shared component needs store data, the caller passes it as a prop.

**`auth/`** — standalone. Reads from `authStore` and `appStore` only.
